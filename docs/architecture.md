# v2 架构与发行

## 单一源码

仓库的 `src/` 是页面、89 个观测点、示例和浏览器工具协议的唯一构建输入。`build/manifest.cjs` 声明样式、数据和脚本的加载顺序。旧开发目录、历史 HTML、原始参考 PDF 和既有测试结果都不是构建输入。

同一套源码生成两种品牌：公开版“本地记录工作台”和便携本地版“综测管理器”。品牌替换只作用于界面与 MCP 标识，不替换规则或示例 JSON。内部已有数据格式及数据库键保留兼容。

## 启动与视图

`view-runtime.js` 提供固定区域、页面和服务注册。各模块注册自己的渲染器或装饰服务，最后由 shell 的 `ScoreApp.start()` 显式启动。外层渲染统一调用前后钩子；编辑器、名单、表格等可嵌套渲染，而不是依次覆盖同名全局渲染函数。

`workbench.js` 根据当前班级、搜索范围和待办状态展示下一步入口。它不修改成绩、核对记录或保存版本。基本动线仍为：管理名单 → 数据录入 → 老师核对 → 导出结果。

## 不变的边界

- `engine.js` 和规则 JSON 负责计分及数据结构校验；试算不等于正式核对。
- 修改、撤销、重做沿用修订号与原有确认失效机制。保存模块负责事务、恢复草稿、恢复点及可选文件副本，视图层不另建保存通路。
- 初始化读取失败不能把“未读到”当作空数据并覆盖原版本。只有成功提交才显示已保存。
- AI/MCP 只能读取授权范围并提交待确认草稿；人工确认、奖项审核和老师核对的边界不因界面重构改变。
- HTML 单独运行无需 Node.js、网络服务或第三方运行时。只有可选 MCP 服务需要 Node.js；不会创建开机自启。

## 构建与测试

```sh
npm run build
npm run build:check
npm run test:all
```

构建检查占位符唯一性、加载顺序、脚本语法和提前闭合标签；数据安全编码后嵌入 HTML。脚本 CSP 使用构建生成的 SHA256 白名单，样式保留内联支持，连接范围不因构建放宽。

测试清单为 `tests/test-manifest.cjs`。统一 runner 只统计本次子进程的 `PASS` 行，不信任历史 `*-results.json`。报告绑定执行前后的源码、HTML、规则、契约、构建器、测试、MCP 及辅助文件哈希。`core`、`browser` 是分组检查；只有 `all` 的完整成功报告可供发行。具体数量来自报告，不在文档中固定。

浏览器测试使用独立 headless 上下文和虚构数据；不会连接日常浏览器工作区。Playwright 仅为测试依赖。

## 发行门禁

```sh
node scripts/package.cjs --check-only --report=<完整报告绝对路径> --html=<受测HTML绝对路径> --out=<发行目录绝对路径> --runtime=<便携Node目录绝对路径>
```

去掉 `--check-only` 才写出发行物。运行时目录须含 `node.exe`、`LICENSE.node.txt` 和官方 `SHASUMS256.txt`，并通过 `win-x64/node.exe` 哈希核验。制作 ZIP 时需要 JSZip；它不是应用或 MCP 的运行依赖。

发行脚本要求报告完整、成功、新鲜且覆盖当前全部套件；重新计算当前 binding，并在压缩后再检查同一报告和输入未变化。输出本地 HTML、轻量应用 ZIP、Windows x64 MCP ZIP、公开源码 ZIP及带校验和的发行清单。它不覆盖已解包工具目录或用户生成的客户端配置。

MCP 包的 `web-source/` 包含原样 canonical `build.cjs`、manifest 和 `src/`。运行其中 `build-html.cjs` 可重建字节一致的本地 HTML；源码 ZIP 的默认构建为公开版。归档内不包含真实学生数据、恢复草稿、连接令牌或模型密钥。
